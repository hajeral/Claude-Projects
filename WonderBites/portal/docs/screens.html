Screen & route inventory

Every registered route of the Admin and Merchant portals, grouped by portal and sidebar section, with its in-memory params, the API endpoints it calls and a link that opens it (append -en / -ar to switch language). Generated by qa/build_screens.py from the live route registry and the QA crawl.

Links use plain hash routes (../index.html#route). Params such as id or tab are passed in memory by the app (App.go(name, params)) and kept in sessionStorage, so a bare link to a detail route opens the most recently viewed record (or its list). Portal routes need a session: the link sends you through that portal's sign-in first (demo: any email/password, any 6-digit code except 000000). “On load” endpoints were recorded by the QA render crawl; “actions” are the other api() calls in the screen's module.
